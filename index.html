AIDGO — AI Data Governance Ontology

An OWL ontology for expressing the alignment between ISO/IEC 5259 data quality management requirements and EU AI Act Article 10 data governance obligations, using RDF-star annotated mapping triples with provenance and justification.

Version1.0.0
Created2026-04-13
CreatorAIDGO Project, ADAPT Centre
LicenseCC BY 4.0
StandardISO/IEC 5259-3:2025
RegulationEU AI Act Art. 10 (2024/1689)

Overview

The EU AI Act mandates that providers of high-risk AI systems implement appropriate data governance and management practices (Article 10). ISO/IEC 5259 provides a comprehensive technical framework for managing data quality in analytics and machine learning. AIDGO bridges these two frameworks through a formally defined alignment ontology.

AIDGO introduces three new alignment relation classes — CompletelySatisfies, PartiallySatisfies, and NoMatching — and uses RDF-star (RDF 1.2 annotated triples) to attach these relations, justifications, and provenance directly to the mapping assertions.

Alignment Relations — New AIDGO Terms

AIDGO introduces three new OWL classes as subtypes of aidgo:AlignmentRelation. These are the core contribution of the ontology, used as type annotations on RDF-star quoted triples.

NEW owl:Class aidgo:CompletelySatisfies
IRIhttps://w3id.org/aidgo#CompletelySatisfies
rdfs:subClassOfaidgo:AlignmentRelation
skos:definitionAn alignment relation indicating that the ISO/IEC 5259 requirement completely addresses all semantic content of the corresponding EU AI Act obligation — same scope, same actors, same data objects, no material gaps.
skos:scopeNoteUse when: (1) the ISO clause covers the full semantic extent; (2) actors, data objects and normative level match; (3) no sub-element of the legal obligation is unaddressed.
ExampleISO 5259-3 §6.3.2 completely satisfies EU AI Act Art. 10(2) data governance practices obligation.
VisualCompletelySatisfies
NEW owl:Class aidgo:PartiallySatisfies
IRIhttps://w3id.org/aidgo#PartiallySatisfies
rdfs:subClassOfaidgo:AlignmentRelation
skos:definitionAn alignment relation indicating that the ISO/IEC 5259 requirement addresses the core intent of the corresponding EU AI Act obligation but contains one or more gaps: (a) narrower scope, (b) missing sub-elements, (c) different actor framing, or (d) different specificity level.
skos:scopeNoteAlways document the gap in aidgo:alignmentGap. Always provide aidgo:recommendedStandard where applicable.
ExampleISO 5259-3 §7.3.5.2 partially satisfies EU AI Act Art. 10(2)(f) — covers technical bias but not the fundamental rights framing.
VisualPartiallySatisfies
NEW owl:Class aidgo:NoMatching
IRIhttps://w3id.org/aidgo#NoMatching
rdfs:subClassOfaidgo:AlignmentRelation
skos:definitionAn alignment relation indicating that no ISO/IEC 5259 requirement addresses the corresponding EU AI Act obligation. This represents a genuine regulatory gap where compliance with ISO 5259 alone is insufficient.
skos:scopeNoteUse when the legal obligation operates in a domain (e.g. personal data law, fundamental rights) structurally outside ISO 5259's scope. Always document in aidgo:alignmentGap and aidgo:recommendedStandard.
ExampleEU AI Act Art. 10(5) special category personal data processing has no matching ISO 5259 requirement.
VisualNoMatching

AlignmentTriple Class

owl:Class aidgo:AlignmentTriple
IRIhttps://w3id.org/aidgo#AlignmentTriple
skos:definitionA named node representing an RDF-star annotated alignment between one EU AI Act legal requirement and one ISO/IEC 5259 technical requirement, qualified with an alignment relation type, justification, basis, and provenance.

Properties of AlignmentTriple

owl:ObjectProperty aidgo:legalRequirement
rdfs:domainaidgo:AlignmentTriple
rdfs:rangeaidgo:LegalRequirement
skos:definitionThe EU AI Act atomic obligation being assessed in this alignment triple.
owl:ObjectProperty aidgo:isoRequirement
rdfs:domainaidgo:AlignmentTriple
rdfs:rangeaidgo:ISORequirement
skos:definitionThe ISO/IEC 5259 atomic requirement being assessed in this alignment triple.
owl:ObjectProperty aidgo:alignmentType
rdfs:rangeaidgo:AlignmentRelation (CompletelySatisfies | PartiallySatisfies | NoMatching)
skos:definitionThe category of alignment for this triple.
owl:DatatypeProperty aidgo:alignmentJustification
rdfs:rangerdf:langString
skos:definitionA 1–3 sentence rationale explaining the alignment decision, documenting both similarities and differences.
owl:DatatypeProperty aidgo:alignmentGap
rdfs:rangerdf:langString
skos:definitionFor PartiallySatisfies and NoMatching: description of what element is missing from the ISO standard.

RDF-star Pattern

AIDGO uses RDF-star (RDF 1.2 Annotated Triples) to attach alignment metadata directly to mapping assertions. This enables SPARQL-star queries that retrieve justification and provenance without reification overhead.

RDF-star quoted triple pattern

# Standard mapping assertion (the "quoted triple")
<legal:AiaPrReq_10.2_1> aidgo:satisfiedBy <iso:AidgoReq_6_3_2> .

# RDF-star annotation — metadata attached to the triple itself
<< <legal:AiaPrReq_10.2_1> aidgo:satisfiedBy <iso:AidgoReq_6_3_2> >>
    aidgo:alignmentType          aidgo:CompletelySatisfies ;
    aidgo:alignmentBasis         aidgo:SemanticEquivalence ;
    aidgo:alignmentJustification "ISO 5259-3 §6.3.2 data quality culture requirements 
    completely satisfy Art 10(2) governance practices."@en ;
    prov:wasGeneratedBy          aidgo:MappingProcess_v1 ;
    prov:generatedAtTime         "2026-04-13"^^xsd:date .

Three RDF-star Patterns

CompletelySatisfies

<< :legalReq aidgo:satisfiedBy :isoReq >>
    aidgo:alignmentType aidgo:CompletelySatisfies ;
    aidgo:alignmentBasis aidgo:SemanticEquivalence ;
    aidgo:alignmentJustification "..."@en ;
    prov:wasGeneratedBy aidgo:MappingProcess_v1 .

PartiallySatisfies

<< :legalReq aidgo:partiallySatisfiedBy :isoReq >>
    aidgo:alignmentType    aidgo:PartiallySatisfies ;
    aidgo:alignmentBasis   aidgo:ScopeOverlap ;
    aidgo:alignmentGap     "Description of what is missing..."@en ;
    prov:wasGeneratedBy    aidgo:MappingProcess_v1 .

NoMatching

<< :legalReq aidgo:satisfiedBy rdf:nil >>
    aidgo:alignmentType         aidgo:NoMatching ;
    aidgo:alignmentBasis        aidgo:GapIdentified ;
    aidgo:alignmentGap          "No ISO 5259 requirement addresses this obligation."@en ;
    aidgo:recommendedStandard   "GDPR Art. 9; ISO/IEC 27701" ;
    prov:wasGeneratedBy         aidgo:MappingProcess_v1 .

SPARQL Queries

These queries use SPARQL-star 1.2 syntax with annotated triple patterns. Load aidgo.ttl into Apache Jena Fuseki, GraphDB, or Stardog to execute them.

CQ-M1: Which ISO clauses completely satisfy Article 10 obligations?

PREFIX aidgo: <https://w3id.org/aidgo#>
PREFIX skos:  <http://www.w3.org/2004/02/skos/core#>
PREFIX dct:   <http://purl.org/dc/terms/>

SELECT ?legalLabel ?isoLabel ?justification WHERE {
  ?mapping a aidgo:AlignmentTriple ;
           aidgo:legalRequirement ?legalReq ;
           aidgo:isoRequirement   ?isoReq ;
           aidgo:alignmentType    aidgo:CompletelySatisfies ;
           aidgo:alignmentJustification ?justification .
  ?legalReq skos:prefLabel ?legalLabel .
  ?isoReq   skos:prefLabel ?isoLabel .
}

CQ-M3: Which Article 10 obligations have no ISO 5259 coverage (gaps)?

SELECT ?legalLabel ?gap ?recommended WHERE {
  ?mapping a aidgo:AlignmentTriple ;
           aidgo:legalRequirement ?legalReq ;
           aidgo:alignmentType    aidgo:NoMatching ;
           aidgo:alignmentGap     ?gap .
  OPTIONAL { ?mapping aidgo:recommendedStandard ?recommended }
  ?legalReq skos:prefLabel ?legalLabel .
}

RDF-star: Query alignment annotations on mapping triples

PREFIX aidgo: <https://w3id.org/aidgo#>

SELECT ?alignmentType ?justification ?generatedAt WHERE {
  # RDF-star pattern: query annotations on the quoted triple
  << ?legalReq aidgo:satisfiedBy ?isoReq >>
      aidgo:alignmentType          ?alignmentType ;
      aidgo:alignmentJustification ?justification ;
      prov:generatedAtTime         ?generatedAt .
}

CQ-M5: Count by alignment type

SELECT ?alignmentType (COUNT(?m) AS ?count) WHERE {
  ?m a aidgo:AlignmentTriple ;
     aidgo:alignmentType ?alignmentType .
} GROUP BY ?alignmentType ORDER BY DESC(?count)
